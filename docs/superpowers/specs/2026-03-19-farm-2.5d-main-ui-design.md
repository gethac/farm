# 2.5D 农场主界面重设计文档

- 日期：2026-03-19
- 主题：保留现有全部功能的前提下，将农场主界面重构为移动端竖屏优先的 2.5D 游戏化 UI
- 状态：已确认设计，待文档审阅

## 1. 目标

将当前偏卡片化、H5 面板化的农场首页，重构为接近参考图的 2.5D 农场游戏主界面。

本次改造不是简单换皮，而是同时调整：

- 视觉风格
- 主界面布局
- 交互方式
- 功能入口组织方式

同时必须满足：

- 当前所有现有功能保留
- 数据流和业务能力尽量复用
- 仅优先支持移动端竖屏

## 2. 设计目标

改造后的主界面需要满足以下判断标准：

1. 第一眼是 2.5D 农场游戏界面，而不是普通 H5 页面
2. 用户始终感觉自己处于同一个农场场景中
3. 地块交互应表现为“点击场景对象”，而非点击卡片按钮
4. 顶部、左侧、底部形成统一 HUD 系统
5. 当前商店、背包、好友、排行、通知、任务等功能都继续可达并可用
6. 主农场界面与次级功能面板拥有统一的视觉语言

## 3. 范围

### 包含

- 农场主界面整体布局重构
- 顶部信息区改造为游戏 HUD
- 左侧快捷功能入口改造
- 底部主导航改造为游戏 tab bar
- 地块渲染方式重构为 2.5D 场景式布局
- 地块点击交互改造成气泡菜单 + 底部 action sheet 的游戏式流程
- 好友农场访问在新场景中的融合
- 任务、商店、背包、排行、通知入口和容器风格重构

### 不包含

- 桌面端优先适配
- 对现有服务端协议进行重写
- 对所有二级功能页业务逻辑做彻底推翻式重构

## 4. 当前问题

当前前端实现存在以下问题：

- 主界面由 `top-bar`、`hero-panel`、`content-panel`、`bottom-nav` 等多个分块区域组成，割裂感明显
- 地块被渲染为规则按钮卡片，缺乏农场场景感
- 视觉上更像管理页或活动页，而不是游戏主界面
- 顶部信息条过于占位，缺少手游 HUD 的轻量悬浮感
- 功能入口组织方式偏 Web 页面，不符合参考图中的游戏交互逻辑

相关现有实现主要位于：

- `apps/web/src/app/App.tsx`
- `apps/web/src/features/farm/FarmScreen.tsx`
- `apps/web/src/features/farm/FarmTopBar.tsx`
- `apps/web/src/features/farm/FarmSlot.tsx`
- `apps/web/src/styles/global.css`

## 5. 总体方案

采用“主界面场景式重构 + 次级功能渐进融合”的方案。

### 总体策略

- 农场主界面按参考图风格重构为单屏 2.5D 场景
- 现有业务逻辑、数据流、事件处理函数尽量保留
- 商店、任务、背包、好友、排行、通知等功能继续保留，但入口位置、容器形式和视觉语言游戏化
- 优先重构主农场体验，不在第一阶段重写所有次级业务页面内部逻辑

这是“设计方向接近方案 A，实施策略按方案 C 落地”的组合方式。

## 6. 信息架构与布局

### 6.1 主界面分层

农场首页将改成单场景结构，分为四层：

1. **背景层**
   - 天空、云、远山、草地、房屋、围栏、道路、木牌等
   - 负责形成完整农场氛围
2. **场景交互层**
   - 农田地块、成熟作物、枯萎作物、锁定地块等
   - 用户主要点击区域
3. **HUD 层**
   - 顶部玩家信息、右上资源、左侧快捷按钮、底部导航
4. **浮层层**
   - 地块操作气泡、底部 action sheet、任务/背包/商店/通知/排行抽屉或面板

### 6.2 主界面结构目标

- 不再保留明显的 hero panel + content panel 分块结构
- 主屏以农场场景为绝对视觉中心
- 主场景尽量持续可见，减少大面积白底卡片遮挡
- 入口以悬浮按钮、图标、气泡、底部导航承担

## 7. 功能映射

### 7.1 顶部玩家信息区

现有 `FarmTopBar` 改为游戏 HUD 顶栏：

- 左上：头像、昵称、等级
- 右上：金币、经验、通知
- 整体采用悬浮条样式，而非整行厚卡片

复用现有数据：

- `displayName`
- `level`
- `coins`
- `experience`
- `notificationCount`

### 7.2 农场主体区

现有 `FarmScreen` 中的 hero 与 content 主区域合并为一个农场场景：

- 房屋、草地、木牌、路径、田地共同构成单一视觉空间
- `slots` 不再表现为规则卡片
- 每个 slot 变成场景中的土地单元
- 通过视觉表现状态，而不是依赖大量静态文案

复用现有能力：

- `slots`
- `selectedSlotId`
- `onSelectSlot`
- `onAction`
- `onRefresh`

### 7.3 地块交互

现有交互为“点地块 → action sheet”。

新交互改为两段式：

1. 点击地块后高亮选中
2. 弹出轻量操作气泡
3. 若操作较多或需要详细信息，再打开底部 action sheet

必须完整保留当前已有地块操作能力，并以 `availableActions` 为准进行呈现，不得在重构中丢失现有动作。

当前需要明确保留的动作包括：

- `plant`
- `water`
- `removeGrass`
- `removeWorms`
- `fertilize`
- `harvest`
- `clearDeadCrop`
- `steal`
- `help`
- `throwWorms`

要求：

- 主界面上优先展示高频动作
- 所有当前动作在新 UI 中都必须仍然可达
- 新 UI 只改变动作入口形式，不改变动作语义与业务约束

### 7.4 左侧快捷功能区

左侧竖向悬浮按钮只承担**快捷入口**职责，不替代一级导航。

建议承载：

- 任务快捷入口
- 通知 / 消息快捷入口
- 其他高频快捷操作入口（若现有功能需要）

约束：

- 左侧入口可以作为快捷方式重复映射已有功能，但不能成为功能唯一入口
- 当前底部主导航中的一级模块，不因放入左侧快捷区而被删除功能可达性
- 左侧入口不承担 `activeTab` 的唯一状态语义，优先用于快速打开对应抽屉、sheet 或覆盖层

### 7.5 底部主导航

现有主导航结构应继续保留 6 个一级模块，以兼容当前 `routes` / `activeTab` 结构：

- 农场（`farm`）
- 商店（`shop`）
- 仓库（`inventory`）
- 任务（`tasks`）
- 好友（`friends`）
- 排行（`ranking`）

底部导航视觉改造为游戏 tab bar：

- 图标 + 标签 + 明显选中态底座
- 风格游戏化，但不随意删减当前一级模块

说明：

- `tasks` 保持为一级功能模块，同时也可以在左侧作为快捷入口镜像存在
- `inventory` 保持在底部一级导航，不迁移为仅左侧入口
- 顶部通知入口继续单独保留，不并入底部导航

### 7.6 好友农场访问

现有 `FarmFriendStrip` 不再作为主屏固定横条。

建议改造为：

- 主界面保留好友入口
- 点击后打开好友列表抽屉 / 面板
- 访问好友农场后仍处于同一套场景 UI
- 顶部 HUD 明确显示当前农场归属
- 帮忙、偷取、捣乱等逻辑继续沿用

### 7.7 商店 / 任务 / 排行 / 通知

这些功能继续保留：

- 入口改为游戏化
- 容器改为抽屉、sheet 或覆盖层
- 业务逻辑与数据流尽量不动
- 与主界面统一样式体系

## 8. 组件与代码结构重组

不建议在现有 `FarmScreen` 上做局部拼补，建议保留业务逻辑、重组视图层。

### 8.1 建议的主场景组件层次

以 `FarmScreen` 为主容器，拆分为以下视图层：

1. `FarmSceneBackground`
   - 背景视觉层
   - 云、天、山、房屋、围栏、道路等
2. `FarmScenePlots`
   - 地块渲染层
   - 负责 2.5D 排列与状态展示
3. `FarmHudTop`
   - 顶部 HUD
4. `FarmHudSideActions`
   - 左侧快捷操作
5. `FarmHudBottomNav`
   - 底部导航
6. `FarmInteractionOverlay`
   - 地块高亮、气泡菜单、提示与弹层入口

### 8.2 对现有组件的处理建议

- `FarmTopBar`：保留数据职责，重写视觉和结构
- `FarmSlot`：从按钮卡片重写为场景土地单元
- `FarmFriendStrip`：退化为好友入口，不再占据主屏横向位置
- `FarmActionSheet`：保留操作逻辑，但重做触发方式和样式
- `AppShell`：弱化卡片壳感，让农场页更接近全屏沉浸式体验

### 8.3 样式体系调整

当前 `global.css` 中大量样式命名体现面板式结构，例如：

- `.top-bar`
- `.hero-panel`
- `.content-panel`
- `.bottom-nav`

这些样式将逐步弱化或替换，转向以下几类样式体系：

- 场景背景样式
- HUD 样式
- 地块样式
- 游戏化浮层样式
- 竖屏安全区样式

### 8.4 与现有状态结构的兼容策略

本次重构优先保持当前前端状态组织不变，只重构视图呈现方式。

明确约束如下：

- `activeTab` 继续作为一级模块切换的核心状态
- `routes` 继续作为底部主导航的数据来源，除非在实现计划阶段明确提出替代方案并单独确认
- `selectedSlotId` 继续承担地块选中状态
- `notificationsOpen` 继续承担通知面板开关状态
- 左侧快捷按钮与顶部入口可以触发 overlay / sheet，但不应与 `activeTab` 的一级模块切换职责冲突

换言之，本次设计的基本方向是：

- 保留现有 store 和路由状态语义
- 允许 UI 容器从“整块主面板”变成“抽屉 / sheet / 覆盖层”
- 但需要为每个模块明确唯一主入口与状态归属，避免同时出现两套互相冲突的容器模型

## 9. 交互设计

### 9.1 地块点击

用户点击地块后：

- 地块出现高亮态
- 伴随底座发光、轻微抬起或强调边框
- 地块附近弹出轻量操作气泡
- 若需更多操作，再弹出底部 action sheet

### 9.2 侧边入口

点击左侧按钮时：

- 以抽屉 / sheet / 浮层展开次级功能
- 主场景背景尽量保持可感知
- 避免整页跳转破坏沉浸感

### 9.3 底部导航

- `farm` 保持在主场景
- 非 `farm` tab 以游戏化面板承载对应功能
- 保持现有路由或状态切换能力，但 UI 呈现改变

### 9.4 好友农场切换

- 进入好友农场后沿用同一场景结构
- HUD 明确显示访问关系
- 可执行动作根据当前农场归属动态变化

## 10. 状态表现规范

现有业务状态保留，但以视觉表达为主。

### 10.1 `empty`

- 翻好的空土地
- 无作物
- 可引导进行种植

### 10.2 `growing`

- 有明显成长中的作物表现
- 至少应传达“幼苗 / 生长中”的感觉

### 10.3 `mature`

- 成熟作物外观明显更饱满、更亮
- 具备明显的“可收获”提示感

### 10.4 `withered`

- 偏灰黄、干枯、缺水或虫害感
- 与成熟态强区分

### 10.5 `locked`

- 地块不可用
- 需要有明确未解锁标识和封锁视觉

## 11. 实现原则

1. **尽量复用数据流**
   - `App.tsx` 中现有请求、刷新、操作函数优先保留
2. **尽量复用事件逻辑**
   - `onSelectSlot`、`onAction`、`onRefresh`、好友访问等能力不推翻
3. **主要重构视图层**
   - JSX 结构和 CSS 体系重组为主
4. **优先完成农场主界面重构**
   - 次级功能页先做容器融合，再视需要细化
5. **只面向移动端竖屏优化**
   - 不为桌面端做同优先级设计

## 12. 验收标准

实现完成后，应至少满足以下标准：

1. 农场首页第一眼就是 2.5D 农场游戏界面
2. 页面不再有明显 hero/content 双分区割裂感
3. 地块交互符合游戏场景点击习惯，而不是卡片按钮习惯
4. 顶部、左侧、底部形成统一 HUD 体系
5. 当前所有核心功能仍然可达、可用
6. 好友、任务、背包、商店、排行、通知能融入新主界面体系
7. 竖屏移动端下主场景为核心，操作层级清晰、无遮挡主要玩法区域

## 13. 风险与控制

### 风险 1：改动面过大

控制方式：

- 优先复用现有业务数据与事件处理
- 将改造集中在渲染层和样式层

### 风险 2：保留全部功能导致界面过载

控制方式：

- 通过 HUD 分层和浮层层级管理信息密度
- 高频功能直达，低频功能放入次级面板

### 风险 3：重构后仍显得像网页

控制方式：

- 避免大面积白底卡片
- 强化场景连续性
- 使用悬浮 HUD、2.5D 地块、游戏 tab bar 和操作气泡

## 14. 下一步

在该设计确认后，下一步应进入实现规划，拆分为：

1. 主场景结构重构
2. 顶部/左侧/底部 HUD 重构
3. 地块 2.5D 渲染与状态表现重构
4. 地块操作交互重构
5. 次级功能入口与弹层融合
6. 移动端竖屏细节与验证
